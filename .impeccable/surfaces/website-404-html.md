# Surface brief: Missing-page recovery

Visitor mode: **Operate** (recover a route).

## Built strategy

An outdated or incomplete link needs a useful next destination, not another
homepage pitch. The first viewport retains the small brand header, one plain
missing-page heading and explanation. Returning to the pilot guide is primary;
client setup is secondary. The MS1 alternative stays an inline note.

The reading frame and wrapping actions share the global system without the
panorama, full portal navigation, fake search or status decoration. Both themes,
native links, skip access and visible keyboard focus work without JavaScript.
Local links use the real `/#getting-started` and `/#downloads` anchors.

## Constraints and basis

Preserve HTTP 404 and noindex/nofollow; a recovery page must not pretend a missing
resource succeeded or imply that public website access opens the private pilot.
Sources: `website/404.html`, the recovery rules in `website/styles.css` and
the static site's existing response override. The shared stylesheet remains a
single related-target match in the homepage brief, not a second route owner.

[DESIGN.md](../../DESIGN.md) owns tokens and native-control rules.
[PRODUCT.md](../../PRODUCT.md) owns availability/distribution truth. This is a
post-build recovery brief within the confirmed existing-world refinement, not
a new seed, generated comp or retroactive human approval. The retained finish
verdict covers supplied recovery UI; it is not deployment or TLS verification.
